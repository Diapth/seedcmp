## 2. Problem Statement

真实业务中的 AI 任务通常不是单轮问答，而是包含需求理解、任务拆解、资料检索、数据处理、内容生成、结果审核和文件交付等多个步骤的复杂流程。普通用户很难稳定地把一个大任务拆成可执行步骤，也很难判断 AI 中间过程是否可靠。

当前常见 AI 工具存在以下问题：

- 复杂任务拆解依赖用户手动提示，门槛高。
- 单个 Agent 同时承担规划、执行、分析和审核，结果稳定性不足。
- 执行过程不可见，用户无法追踪每一步的输入、输出、状态和错误。
- 相似工作流难以复用，每次都要重新组织提示词和材料。
- 输出大多停留在文本层面，缺少 PPT、表格、图表、代码工程等真实可交付产物。
- 缺少知识库、文件解析、搜索、图表、导出、打包等工具能力接入。

因此，需要一个面向复杂工程任务的多 Agent 协作平台，让用户能够用可配置、可观测、可复用的方式完成任务，并获得可预览、可下载、可二次编辑的工程产物。

## 3. Solution

AgentHub 通过多 Agent 分工、工作流编排、工具调用、RAG 知识库、任务运行中心和产物工作区，将复杂任务从单轮回答升级为可追踪的工程自动化流程。

用户输入任务后，系统根据工作流模板自动拆解任务，并调度多个 Agent 依次或并行执行。每个 Agent 承担清晰职责，例如 Planner Agent 负责需求拆解，Research Agent 负责资料检索，Analysis Agent 负责结构化分析，Builder Agent 负责生成文件，Reviewer Agent 负责质量审核。系统在前端展示执行状态、中间输出、错误信息和最终结果，并将结果沉淀为 Markdown 报告、PPTX、Excel/CSV、图表、代码工程 ZIP 包等产物。

MVP 阶段优先跑通 3 个高质量模板：

- PPT 自动制作
- 表格数据分析
- Vue3 小游戏或简单代码工程生成

平台化阶段再扩展 Agent 自定义、工作流模板管理、RAG 知识库、工具绑定、产物版本管理和更多业务模板。

## 4. 产品目标

### 4.1 核心目标

- 构建一个可运行的多 Agent 协作平台。
- 支持用户创建任务并选择工作流模板。
- 支持固定模板下的多 Agent 顺序执行。
- 支持展示每个 Agent 的执行状态、中间输出、错误信息和最终结果。
- 支持上传资料并用于 RAG 检索增强。
- 支持生成 Markdown 报告、PPTX、Excel/CSV 分析结果、图表和代码工程文件。
- 支持产物预览、下载和任务历史记录。
- 通过完整前后端、数据库、异步任务、AI 编排、文件生成和部署能力体现全栈工程能力。

### 4.2 非目标

- MVP 不做通用低代码平台。
- MVP 不做任意复杂拖拽编排。
- MVP 不承诺支持任意类型的代码工程生成。
- MVP 不做复杂企业权限体系。
- MVP 不追求覆盖所有模型、所有工具和所有文件格式。
- MVP 不以移动端体验为主，uni-app 或移动端仅作为后续扩展。

需要快速生成 PPT、表格分析、图表看板、竞品报告、商品卖点分析和营销材料的人群。

## 6. 核心场景

### 6.1 PPT 自动制作

用户输入主题、受众、页数、风格，或上传参考资料。系统自动完成任务拆解、资料提取、大纲生成、页面文案、讲稿、视觉建议和 PPTX 文件生成。

最终产物：

- PPT 大纲
- 每页标题与要点
- 演讲备注
- PPTX 文件
- 可下载素材包

### 6.2 表格数据分析

用户上传 Excel 或 CSV 数据。系统识别字段，完成数据清洗、统计分析、异常识别、图表生成和业务结论归纳。

最终产物：

- 清洗后的数据表
- 统计汇总表
- 可视化图表
- 分析结论
- Excel/CSV/Markdown 或 PDF 报告

### 6.3 小游戏与简单代码工程生成

用户输入简单项目需求。系统自动生成需求拆解、技术方案、项目结构、代码文件、运行说明和验收清单。

最终产物：

- 项目结构
- 源代码文件
- README 运行说明
- 手动验收清单
- 可下载 ZIP 包
- 可预览页面

### 6.4 竞品分析

用户输入品牌、商品或资料。系统拆解分析维度，整理价格、产品、营销、评论等信息，生成结构化竞品分析报告。

最终产物：

- 竞品对比表
- 优劣势分析
- 市场策略建议
- 风险点总结
- Markdown 或 PDF 报告

### 6.5 文档问答与报告生成

用户上传 PDF、Markdown、TXT、CSV 或 DOCX 文件。系统解析、切分、向量化并检索资料，再由多个 Agent 协作生成摘要、问答结果或结构化报告。

## 8. 功能需求

### 8.1 Agent 管理

- 用户可以创建 Agent。
- 用户可以编辑 Agent 名称、角色、描述和系统提示词。
- 用户可以配置模型名称、温度等基础参数。
- 用户可以为 Agent 绑定可用工具。
- 用户可以查看 Agent 历史执行记录。
- 系统内置 Planner、Research、Analysis、Writer、Builder、Tester、Reviewer 等基础 Agent。

### 8.2 工作流编排

- 用户可以选择内置工作流模板。
- 系统可以按模板配置 Agent 执行顺序。
- MVP 先支持串行执行。
- 后续支持部分并行、人工确认节点和模板复用。
- 工作流需要明确每一步输入、输出和下游依赖。

### 8.3 任务运行中心

- 用户可以创建任务并输入任务目标。
- 用户可以选择任务对应的工作流模板。
- 系统需要记录任务状态：Pending、Running、Completed、Failed、Cancelled。
- 用户可以查看每个 Agent 的执行状态、输入、输出、错误信息和耗时。
- 用户可以查看最终报告或工程产物。
- 用户可以重新运行失败或历史任务。

### 8.4 工具管理

- 系统可以注册工具。
- 系统可以为不同 Agent 配置可调用工具。
- 系统需要记录工具调用日志。
- 工具调用需要包含入参、出参、调用状态、耗时和错误信息。
- MVP 支持文件解析、RAG 检索、图表生成、报告导出、PPTX 生成、Excel/CSV 分析、代码工程生成和 ZIP 打包。

### 8.5 RAG 知识库

- 用户可以上传 PDF、TXT、Markdown、CSV、DOCX 文件。
- 系统可以解析上传文件并生成文本内容。
- 系统可以将文档切分为知识片段。
- 系统可以为知识片段生成向量并存储。
- Agent 可以基于任务上下文检索相关知识片段。
- 检索结果需要保留来源信息，便于结果溯源。

### 8.6 结果输出

- 系统可以输出 Markdown 报告。
- 系统可以输出结构化表格。
- 系统可以输出图表。
- 系统可以导出 PDF。
- 系统可以导出 PPTX。
- 系统可以导出 Excel/CSV。
- 系统可以导出代码工程 ZIP 包。
- 系统可以提供复制、预览、下载能力。

### 8.7 工程产物工作区

- 用户可以查看一个任务生成的全部文件。
- 用户可以预览 Markdown、表格、图表和代码文件。
- 用户可以下载单个文件。
- 用户可以下载完整产物包。
- 用户可以对生成内容进行二次编辑。
- 系统可以保存不同版本的产物。

## 10. 核心流程

### 10.1 通用任务执行流程

1. 用户创建任务并输入目标。
2. 用户选择工作流模板。
3. 后端创建任务记录。
4. 任务进入异步队列。
5. Worker 执行多 Agent 工作流。
6. 每个 Agent 读取上一步输出并生成本步结果。
7. 工具层提供检索、文件解析、图表、导出、打包等能力。
8. 后端记录中间结果、日志、错误和产物元数据。
9. 前端展示任务状态和 Agent 执行过程。
10. 系统生成最终报告或工程产物。
11. 产物工作区提供预览、下载和二次编辑。

### 10.2 PPT 生成流程

1. Planner Agent 拆解 PPT 结构。
2. Research Agent 从资料或知识库提取关键信息。
3. Outline Agent 生成页面大纲。
4. Slide Writer Agent 生成每页标题、要点和讲稿。
5. Visual Agent 生成配色、图表和排版建议。
6. Builder Agent 输出 PPTX 文件。
7. Reviewer Agent 检查页数、逻辑顺序和内容完整性。

### 10.3 表格分析流程

1. Data Reader Agent 读取 Excel/CSV。
2. Data Cleaner Agent 处理缺失值、异常值和字段类型。
3. Analyst Agent 完成分组统计、趋势分析和异常检测。
4. Chart Agent 生成柱状图、折线图、饼图等图表。
5. Insight Agent 归纳业务结论和建议。
6. Builder Agent 输出表格、图表和报告。
7. Reviewer Agent 校验统计口径和结论一致性。

### 10.4 代码工程生成流程

1. Product Agent 将需求拆解为功能清单。
2. Architect Agent 设计技术方案和项目结构。
3. Frontend Agent 生成页面、组件和样式代码。
4. Logic Agent 生成业务逻辑或游戏逻辑。
5. Tester Agent 生成测试点和验收清单。
6. Builder Agent 打包项目文件并生成运行说明。
7. Reviewer Agent 检查代码完整性和运行步骤。

## 11. Implementation Decisions

- MVP 采用模板式工作流，而不是复杂拖拽编排，优先保证演示稳定性。
- MVP 至少内置 Planner、Research、Analysis、Builder、Reviewer 5 类 Agent。
- Agent 的输入输出需要结构化，避免多轮传递时信息丢失。
- 多 Agent 编排层采用有状态工作流，便于记录每一步执行状态。
- 长耗时任务采用异步队列执行，避免接口请求阻塞。
- 前端通过任务运行中心展示步骤状态、中间输出和最终产物。
- 任务状态统一为 Pending、Running、Completed、Failed、Cancelled。
- 工程产物统一抽象为 Artifact，支持报告、PPTX、Excel、CSV、图表、代码工程、ZIP 包等类型。
- 知识库采用文档解析、文本切分、向量化存储和相似度检索流程。
- RAG 检索结果需要保留来源信息和片段元数据。
- 文件存储用于保存用户上传资料、生成报告和代码工程产物。
- 前端建议使用 Vue 3、Vite、TypeScript、Vue Router、Pinia、Element Plus 或 Naive UI。
- 工作流可视化建议使用 Vue Flow。
- 图表展示建议使用 ECharts。
- 后端建议使用 FastAPI、Python、SQLAlchemy、Pydantic、Celery 或 RQ。
- 缓存与任务队列建议使用 Redis。
- 结构化数据建议使用 PostgreSQL。
- 向量检索建议优先使用 pgvector，降低部署复杂度。
- AI 编排建议使用 LangGraph，工具接入和文档处理可结合 LangChain。
- PPT 生成建议使用 python-pptx。
- 表格处理建议使用 pandas 与 openpyxl。
- 工程打包可使用后端压缩工具。
- 本地部署建议提供 Docker Compose，一键启动前端、后端、数据库和 Redis。

## 13. 验收标准

### 13.1 MVP 验收标准

- 用户可以创建一个任务。
- 用户可以选择至少一个内置工作流模板。
- 系统可以自动执行多个 Agent。
- 页面可以展示每个 Agent 的执行状态和中间输出。
- 系统可以生成至少一种可下载工程产物。
- 用户可以在产物工作区预览或下载结果。
- 用户可以查看历史任务。
- 失败任务能展示失败步骤和错误信息。
- 项目 README 包含项目简介、技术栈、启动方式、演示场景和截图位置。
- 本地环境可以通过明确命令启动核心服务。

### 13.2 答辩验收标准

- 能完整演示从任务输入到产物下载的闭环。
- 能展示多 Agent 分工和执行流程。
- 能展示 RAG、工具调用或产物生成中的至少一个技术亮点。
- 能说明系统架构、数据模型和核心技术选型。
- 能说明 MVP 范围控制和后续扩展路线。

## 14. Testing Decisions

- 测试应关注外部行为，不测试内部实现细节。
- 工作流编排测试重点验证 Agent 执行顺序、状态流转、失败中断和重试逻辑。
- 任务运行测试重点验证任务创建、状态更新、中间输出记录和最终结果保存。
- Artifact 测试重点验证产物类型、文件路径、预览地址和下载能力。
- RAG 测试重点验证文档解析、切分、检索结果相关性和来源信息。
- 表格分析测试重点验证字段识别、清洗规则、统计口径和图表数据一致性。
- PPT 生成测试重点验证页数、标题、内容结构和文件可打开。
- 代码工程生成测试重点验证项目结构、依赖说明、核心文件完整性和运行说明。
- 前端测试重点验证任务创建表单、任务运行中心、产物工作区和错误状态展示。
- 端到端测试至少覆盖一个完整模板：创建任务、执行 Agent、生成产物、预览和下载。
- 当前仓库暂无源码测试先例，落地实现时需要随核心模块同步补充单元测试、集成测试和手动验收清单。

## 15. Out of Scope

- 不在 MVP 阶段实现任意工作流拖拽编排。
- 不在 MVP 阶段支持任意复杂代码项目生成。
- 不在 MVP 阶段实现完整移动端应用。
- 不在 MVP 阶段实现复杂组织、角色、权限和计费系统。
- 不在 MVP 阶段实现所有文件格式解析。
- 不在 MVP 阶段实现真实支付、订单或商业化流程。
- 不在 MVP 阶段保证模型输出完全无幻觉，需通过 RAG、结构化输出和 Reviewer 降低风险。

## 16. 风险与应对

### 16.1 范围过大

风险：AgentHub 容易扩展成过大的平台，导致比赛周期内无法完成。

应对：MVP 聚焦固定模板和完整闭环，优先保证可演示、可下载、可解释。

### 16.2 模型输出不稳定

风险：多个 Agent 连续调用时，错误可能逐步放大。

应对：为每个 Agent 定义明确输入输出格式，并使用 Reviewer Agent 做最终检查。

### 16.3 RAG 效果不佳

风险：文档切分和检索质量会影响生成结果。

应对：控制文档切片长度，保留元数据，优先支持结构简单的 PDF、Markdown、TXT、CSV。

### 16.4 演示数据不足

风险：PPT、表格分析和代码生成场景需要稳定素材，否则答辩演示效果不稳定。

应对：MVP 内置答辩 PPT 示例资料、商品销售 CSV 示例数据和小游戏需求模板。

### 16.5 代码工程无法运行

风险：生成工程可能存在依赖缺失、语法错误或说明不完整。

应对：限制 MVP 工程模板范围，优先支持 Vue3 单页小游戏或静态页面项目，并由 Tester Agent 输出验收清单。

## 17. 里程碑

### 17.1 第一阶段：MVP 演示版本

目标：跑通从任务输入到多 Agent 协作生成工程产物的完整闭环。

交付内容：

- 内置 3 到 5 个 Agent
- 内置至少 1 个稳定工作流模板
- 任务创建与运行状态展示
- Agent 中间输出展示
- Markdown 报告或工程产物生成
- 产物预览与下载
- 任务历史记录

### 17.2 第二阶段：平台化版本

目标：从固定 Demo 升级为可配置平台。

交付内容：

- Agent 创建与编辑
- 工作流模板管理
- 工具绑定
- RAG 知识库上传
- 文档解析与向量检索
- 任务运行日志
- 用户登录
- 产物工作区
- PPT、表格分析、代码工程模板

### 17.3 第三阶段：答辩增强版本

目标：增强展示效果和项目完整度。

交付内容：

- 工作流可视化图
- Agent 执行耗时统计
- Token 消耗统计
- 审核 Agent 评分
- 人工介入修改
- 多模型切换
- 代码工程在线预览
- PPT 页面预览
- 表格分析图表看板
- README、架构图、接口文档和演示视频

## 18. Further Notes

AgentHub 的核心价值是将 AI 从单点问答工具升级为复杂工程任务协作平台。比赛项目应避免一开始追求大而全，优先完成一个稳定、可展示、可下载产物的闭环系统，再逐步扩展为通用 Agent 工程协作平台。

推荐 MVP 演示顺序：

1. 创建一个 PPT 生成任务，展示多 Agent 执行与 PPTX 产物。
2. 创建一个表格分析任务，展示文件上传、数据处理、图表和报告。
3. 创建一个小游戏工程生成任务，展示代码产物、ZIP 下载和运行说明。

README 建议包含项目简介、核心功能、系统架构图、技术栈、快速启动方式、演示截图、演示场景、工程产物展示、项目路线规划和团队分工。
