## 2. US1 日常消息收发

**目标**：验证可靠的消息发送、接收、媒体、消息操作、反应、回执、置顶、提醒功能

**前置**：完成[基础登录](#13-基础登录流程)，准备两个账号互相发送消息

### 2.1 文本消息发送

**步骤：**
1. 在会话列表点击一个**单聊**会话
2. 在输入框输入测试文本（如 `US1-文本测试-001`）
3. 按 `Enter` 发送
4. 观察消息出现在消息列表中

**预期：**
- 消息气泡正确渲染，包含发送者头像、时间戳
- 消息状态显示已发送
- 刷新页面后消息仍然存在

**通过标准**：✅ 消息发送成功，刷新后状态保留

---

### 2.2 媒体发送（图片）

**步骤：**
1. 点击输入框左侧的**图片/文件上传**按钮
2. 选择一张本地图片（小于后端限制）
3. 确认上传，等待预览出现
4. 按 `Enter` 或点击发送按钮发送

**预期：**
- 图片预览气泡正确显示缩略图
- 点击图片可放大预览
- 刷新后图片消息仍然可见

**通过标准**：✅ 图片消息发送成功，预览正常，刷新后状态保留

---

### 2.3 媒体发送（文件）

**步骤：**
1. 点击输入框左侧的**图片/文件上传**按钮
2. 选择一个本地文件（PDF、Word 等）
3. 确认上传，等待文件名预览出现
4. 发送文件消息

**预期：**
- 文件消息气泡显示文件名、文件大小图标
- 点击可触发下载
- 刷新后文件消息仍可见

**通过标准**：✅ 文件消息发送成功，下载正常，刷新后状态保留

---

### 2.4 消息回复

**步骤：**
1. 在消息列表中找到一条已有消息
2. 鼠标右键点击该消息，弹出上下文菜单
3. 点击**回复**
4. 输入回复内容（如 `US1-回复测试-001`）
5. 发送

**预期：**
- 回复气泡显示被回复的消息引用（被回复者头像 + 引用文字）
- 回复内容正确显示

**通过标准**：✅ 回复消息正确显示引用关系

---

### 2.5 消息编辑

**步骤：**
1. 在消息列表中找到自己发送的一条文本消息
2. 鼠标右键点击该消息，弹出上下文菜单
3. 点击**编辑**
4. 修改消息内容（如改为 `US1-编辑后-001`）
5. 确认保存

**预期：**
- 消息内容更新为新文本
- 消息气泡显示"已编辑"标识
- 对方收到更新后的消息

**通过标准**：✅ 编辑成功，编辑标识可见，对方端同步更新

---

### 2.6 消息删除

**步骤：**
1. 在消息列表中找到自己发送的一条消息
2. 鼠标右键点击，弹出上下文菜单
3. 点击**删除**
4. 在弹出的确认对话框中点击**确认**

**预期：**
- 消息从列表中消失，或显示"你撤回了一条消息"占位
- 对方端该消息同步消失或显示对应占位

**通过标准**：✅ 删除成功，双方状态同步

---

### 2.7 消息反应

**步骤：**
1. 在消息列表中找到一条消息（对方发送的）
2. 鼠标悬停在该消息上，显示操作栏
3. 点击**表情**按钮
4. 选择一个 emoji 表情（如 👍）

**预期：**
- 表情出现在消息下方
- 同一用户点击相同表情会取消

**通过标准**：✅ 反应添加成功，再次点击取消成功

---

### 2.8 已读回执

**步骤：**
1. 使用账号 A 向账号 B 发送一条消息
2. 在账号 B 的同一会话中查看该消息（不发送任何消息）
3. 切换回账号 A，查看消息状态

**预期：**
- 消息下方显示"已读"标识（双勾）
- 或者在对方未读时显示"未读"标识（单勾）

**通过标准**：✅ 回执状态正确显示（取决于对方是否已读）

---

### 2.9 置顶消息

**步骤：**
1. 在消息列表中找到一条消息
2. 鼠标右键点击，弹出上下文菜单
3. 点击**设为置顶**
4. 刷新页面
5. 在会话中再次右键该消息，点击**取消置顶**

**预期：**
- 置顶后刷新消息仍保持置顶状态
- 取消置顶后消息恢复正常排序

**通过标准**：✅ 置顶状态刷新后保留，取消置顶后恢复正常

---

### 2.10 消息提醒

**步骤：**
1. 在消息列表中找到一条消息
2. 鼠标右键点击，弹出上下文菜单
3. 点击**提醒我**
4. 选择一个提醒时间（1小时后/明天/自定义）
5. 等待提醒时间到达，观察是否有提醒通知

**预期：**
- 设置成功后显示提醒标记
- 到达提醒时间时浏览器弹出通知或应用内提示

**通过标准**：✅ 提醒设置成功（通知触发取决于后端和浏览器权限）

---

### 2.11 离线消息接收

**步骤：**
1. 账号 A 和账号 B 建立会话
2. 账号 B 断开网络（飞行模式或关闭WiFi）
3. 账号 A 向账号 B 发送一条消息（如 `US1-离线测试-001`）
4. 账号 B 恢复网络连接
5. 观察账号 B 是否收到离线消息

**预期：**
- 重连后，离线消息自动出现在消息列表中
- 未读计数正确更新

**通过标准**：✅ 离线消息在重连后正确接收，未读计数准确

---

### 2.12 US1 总体通过标准

- [ ] 文本消息发送成功，刷新后保留
- [ ] 图片/文件消息发送成功，预览正常
- [ ] 回复、编辑、删除操作正确执行并同步
- [ ] 反应添加/取消正常
- [ ] 已读回执状态正确
- [ ] 置顶消息刷新后保留
- [ ] 离线消息重连后正确接收
- [ ] 无浏览器原生 alert/confirm/prompt 弹窗

## 3. US2 群组管理

**目标**：验证群资料、成员、邀请、QR码、角色、禁言、黑名单、所有权转移、退出、解散等完整流程

**前置**：完成[基础登录](#13-基础登录流程)，进入一个**群聊**会话

### 3.1 群聊入口和基础设置

**步骤：**
1. 在会话列表中找到并点击一个**群聊**会话
2. 点击会话顶部的**群聊设置**按钮（通常在右上角）
3. 观察群聊信息抽屉是否正确展开

**预期：**
- 抽屉显示群名称、群头像、群公告
- 显示群二维码入口
- 显示邀请确认、全员禁言等开关
- 显示邀请成员按钮

**通过标准**：✅ 群聊设置抽屉正常展开，所有基础入口可见

---

### 3.2 群二维码（QR码）

**步骤：**
1. 在群聊设置抽屉中点击**群二维码**
2. 观察是否显示二维码

**预期：**
- 二维码正确生成并显示
- 显示保存图片/分享按钮

**通过标准**：✅ 二维码显示正常

---

### 3.3 邀请成员

**步骤：**
1. 在群聊设置抽屉中点击**邀请成员**
2. 在联系人列表中选择一个或多个成员
3. 点击确认邀请
4. 观察被邀请成员是否出现在群成员列表中

**预期：**
- 邀请成员弹窗正常打开
- 联系人选择功能正常
- 邀请成功后成员加入群聊

**通过标准**：✅ 邀请成员功能正常，被邀请人成功加入

---

### 3.4 扫码入群（QR码扫描加入）

**步骤：**
1. 辅助测试账号 B 打开群二维码
2. 使用另一个设备扫描该二维码
3. 观察是否出现入群申请或直接入群

**预期：**
- 扫码后出现加群入口或申请确认界面
- 根据群设置（是否需要确认）出现对应流程

**通过标准**：✅ 扫码入口可用，流程符合群设置（需确认或直接加入）

---

### 3.5 全员禁言

**步骤：**
1. 以群主/管理员身份进入群聊设置
2. 找到**全员禁言**开关
3. 开启全员禁言
4. 切换到普通成员账号，尝试在群中发送消息
5. 关闭全员禁言，再次尝试发送消息

**预期：**
- 开启禁言后，普通成员输入框显示禁用状态或发送失败
- 群主/管理员仍可发送消息
- 关闭禁言后所有成员恢复正常发送

**通过标准**：✅ 禁言开关正确控制成员发送权限

---

### 3.6 成员角色管理（设置管理员）

**步骤：**
1. 以群主身份进入群成员列表
2. 点击一个普通成员，点击**设为管理员**
3. 确认操作
4. 观察该成员是否获得管理员权限（出现在管理员列表）

**预期：**
- 管理员设置操作正常执行
- 被设置的管理员在群聊设置中看到更多管理选项

**通过标准**：✅ 管理员设置成功，权限正确同步

---

### 3.7 转让群主

**步骤：**
1. 以群主身份进入群成员列表
2. 点击一个成员，选择**转让群主**
3. 确认转让
4. 观察群主权限是否成功转移

**预期：**
- 转让操作弹出确认对话框
- 确认后原群主变为普通成员，新群主获得全部管理权限

**通过标准**：✅ 转让群主成功，权限正确转移

---

### 3.8 移出成员

1. 以群主/管理员身份进入群成员列表
2. 点击一个成员，选择**移出群聊**

## 4. US3 网络恢复与实时可靠性

**目标**：验证连接状态可见、重连行为、离线队列保留、恢复同步、多设备踢出处理，以及**所有消息和状态变更的实时推送（无需刷新直接接收）**

**前置**：完成[基础登录](#13-基础登录流程)；准备两个浏览器/设备分别登录账号 A 和账号 B

### 4.1 连接状态指示器

**步骤：**
1. 登录后观察页面顶部或底部是否有**连接状态指示器**
2. 正常状态下应显示"已连接"或绿色标识
3. 手动断开网络（飞行模式），观察指示器变化
4. 恢复网络连接，观察指示器是否恢复

**预期：**
- 有用户可见的连接状态提示（如"正在连接..."、"已连接"、"连接失败"）
- 离线时显示离线状态
- 重连后自动恢复，显示重连成功

**通过标准**：✅ 连接状态指示器存在且状态切换正确

---

### 4.2 离线队列（消息发送队列）

**步骤：**
1. 在单聊中开始输入一条消息（不发送）
2. 手动断开网络
3. 点击发送消息
4. 观察消息状态（应显示"发送中"或"等待网络"）
5. 恢复网络连接
6. 观察之前发送的消息是否自动发送成功

**预期：**
- 离线发送的消息进入待发送队列
- 消息显示"等待发送"或"发送失败"状态
- 网络恢复后，队列中的消息自动发送成功

**通过标准**：✅ 离线消息进入队列，网络恢复后自动发送

---

### 4.3 重连后数据恢复

**步骤：**
1. 确保会话中有足够的消息记录
2. 断开网络连接
3. 等待30秒以上
4. 恢复网络连接
5. 等待重连完成
6. 检查：
   - 会话列表是否正确恢复
   - 消息列表是否完整
   - 未读计数是否正确
   - 群成员列表是否更新

**预期：**
- 重连后消息列表与断连前一致
- 未读计数正确反映未读消息数量
- 置顶消息、群公告等状态正确恢复

**通过标准**：✅ 重连后数据完整性验证通过

---

### 4.4 多设备踢出处理

**步骤：**
1. 在账号 A 的浏览器中登录
2. 在另一个设备或浏览器中使用同一账号 A 登录
3. 观察第一个设备的行为

**预期：**
- 原登录设备检测到被踢出
- 显示踢出提示（如"您的账号已在其他设备登录"）
- 点击确认后重新跳转到登录页面
- 本地敏感数据（会话消息、联系人等）被正确清理

**通过标准**：✅ 踢出事件正确处理，不泄露敏感数据

### 4.5 实时消息同步（无需刷新直接接收）

> **核心测试原则**：以下所有场景均需在**两个浏览器/设备**上同时操作。账号 A 保持页面不动，账号 B 执行操作，观察账号 A 是否在**不刷新**的情况下实时接收到变更。

#### 4.5.1 对方发送文本消息 → 实时接收

**前置**：账号 A 打开与账号 B 的单聊会话（不发送任何消息，保持页面不动）

**步骤：**
1. 账号 B 在同一会话中发送一条文本消息（如 `实时同步-001`）
2. 立即切换到账号 A 的浏览器（不刷新页面）
3. 观察账号 A 的消息列表

**预期：**
- 新消息**无需刷新**，立即出现在账号 A 的消息列表底部
- 未读计数 +1
- 消息气泡正确渲染（头像、时间、内容）
- 如果账号 A 在另一会话，当前会话入口显示未读红点

**通过标准**：✅ 对方消息实时推送，无延迟感知，无刷新

## 附录：常见问题排查

| 问题 | 可能原因 | 解决方案 |
|---|---|---|
| 登录后页面空白 | 后端服务未启动 | 确认 TangSengDaoDaoServer 和 WuKongIM 已启动 |
| 消息发送失败 | 网络断开 | 检查网络连接和 WebSocket 地址配置 |
| 深色模式刷新后丢失 | localStorage 被清除 | 确认浏览器允许 localStorage |
| 群设置看不到某些按钮 | 非群主/管理员 | 使用群主或管理员账号重新测试 |
| 通知权限状态不正确 | 浏览器版本不支持 | 确认使用支持的浏览器版本 |
| QR登录无法确认 | 需要手机端配合 | 需要真实手机端扫码，烟雾测试仅验证 UI 状态 |
| 举报/机器人不可用 | 后端未配置对应功能 | 确认后端是否已启用相关接口 |
