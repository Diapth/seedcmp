# V3-28 修复计划

## Summary
修复 Clowder/coordinator 近期回归中的四类问题：引用回复缺少上下文且发送后引用预览不清空；群聊中猫猫/协调者回复身份在占位、流式、最终消息和刷新后不稳定；新增猫猫角色模板来源合并后出现重复项；Codex 创建猫猫流程缺少明确、可校验的模型选择。

## Key Changes
- 引用回复链路：
  - 在 `messageStore.sendMessage()` 成功完成本地发送后立即清理 `replyTarget`，不等待 Clowder 路由或流式回复结束。
  - 确保发送 payload 和本地 optimistic message 都携带 quote metadata，包括 quoted message id/seq、author、text、fromUID、conversation id，以及可解析的 `catId/coordinator` 信息。
  - `MessageInput.vue` 只展示当前 composer 的引用预览；已发送引用必须进入消息行，由 `MessageList.vue` 渲染一次，避免底部引用卡片残留。
  - Clowder 路由失败时只更新对应已发送消息的错误/重试状态，不重新挂回旧 `replyTarget`。
- 自动回复路由：
  - 扩展 `clowderGroupAutoReplyPolicy`，新增或完善 `reply_to_cat`、`reply_to_coordinator` 判定。
  - 当新消息文本很短但引用目标是 Clowder cat/coordinator 消息时，仍按被引用 agent 线程继续路由。
  - 将 quote context 写入 Clowder `promptContext`，让模型能看到被引用消息的作者、正文、消息 id/seq 和解析出的目标 agent。
- 身份规范化：
  - 建立统一的 Clowder message identity normalizer，优先使用结构化字段：`catId`、`agentId`、`senderType`、`coordinator` 标记、avatar、displayName。
  - 让 optimistic placeholder、thinking row、streaming chunk、final callback、history hydration、sidebar digest 使用同一套 canonical identity。
  - 明确 `PM` 与 `协调者` 的关系：如果 `PM` 只是协调者昵称，展示层统一显示一个 canonical 名称，别名只保留为 metadata。
  - 禁止用最新 human sender 或文本前缀覆盖已经识别为 cat/coordinator 的回复行身份。
- 角色模板去重：
  - 以 `sections/clowder-ai/cat-template.json` 的 `roleTemplates` 为 cloneable template 主来源。
  - `normalizeRoleTemplates()` 合并 templates、breeds、runtime connected cats、legacy disconnected candidates 时使用稳定 logical key，例如 `roleTemplateId` 优先，其次 `catId/templateId/platform+role`。
  - 去重不能只按 display name；同名但不同模板要保留，逻辑相同但来自不同来源的项折叠为一项。
  - `协调者` 模板创建新猫猫时必须使用 template identity，不能误绑定到内置 coordinator runtime identity。
- Codex 模型选择：
  - 为 Codex/Claude Code 平台补齐模型 metadata：默认模型、允许模型列表、禁用原因、可用性校验。
  - `ClowderCatConsolePage.vue` 在选择 Codex 平台时显示 model selector，默认选中推荐模型，并允许选择 `GPT-5.5`、`GPT-5.4`、`GPT-5.4-Mini` 等可用项。
  - 创建猫猫请求携带 `defaultModel`，并沿用既有 `/cats new ... --model <model>` 路径传给 TangSeng/Clowder。
  - 后端和 Clowder runtime catalog 持久化所选模型，非法或不可用模型返回可见校验错误。

## API / Types
- 扩展引用消息类型：
  - `ReplyReference { messageId; messageSeq; conversationId; authorName; authorUid; text; targetCatId?; targetAgentId?; targetType? }`
  - `ClowderPromptContext.replyReference` 保存给 Clowder 路由和提示词使用。
- 新增或收敛身份类型：
  - `ClowderCanonicalSender { senderType: 'cat' | 'coordinator'; catId?; agentId?; displayName; avatar?; aliases?: string[] }`
  - 所有消息展示入口通过同一 helper 从 callback、stream event、history record、local optimistic record 生成该结构。
- 调整角色模板类型：
  - `ClowderCatRoleTemplate` 明确区分 `roleTemplateId`、`catId`、`logicalKey`、`source`、`cloneable`、`unavailableReason`。
  - `catRoleTemplates` 保存去重后的 cloneable templates，runtime contacts 仍保存在 `catContactDirectory`。
- 扩展创建猫猫类型：
  - `CreateClowderCatRequest.defaultModel?: string`
  - `ClowderPlatformModelOption { id; label; default?; disabled?; disabledReason? }`
  - `/v1/clowder/cats` 或模板接口返回平台模型 metadata，旧响应缺失时前端使用保守默认值。

## Implementation Steps
1. 先补测试夹具和 failing tests，覆盖引用回复路由、引用预览清理、身份稳定、模板去重和 Codex model selector。
2. 修复 `messageStore` 与 `MessageInput.vue` 的引用生命周期，保证本地发送成功即清空 composer 状态。
3. 修复 `MessageList.vue` 和消息归一化逻辑，让 quote reference 只随消息行渲染，并在刷新后保持一致。
4. 扩展 `clowderGroupAutoReplyPolicy`，把引用 Clowder/cat/coordinator 消息识别为上下文续问，并把 quote context 传入 prompt context。
5. 抽出或收敛 Clowder canonical identity helper，并让 stream merge、final ACK、history hydration、digest 生成共同调用。
6. 调整 `clowderStore`、`clowderCatContacts` 和 `ClowderCatConsolePage.vue` 的模板来源与去重规则。
7. 在前端 API、TangSeng `modules/clowder`、Clowder `ImWebCatCreator` 中贯通 `defaultModel`，并补非法模型校验。
8. 跑单元、Go、Clowder build，再做浏览器 smoke，重点观察发送瞬间、流式中、最终回调和刷新后的身份/引用状态。

## Assumptions
- `PM` 在当前产品语义中是协调者别名，而不是独立 runtime agent；如果后续确认是独立 agent，需要在 catalog 中显式建两个不同 identity。
- 引用预览清空以本地发送成功为准；后续 Clowder 失败只影响已发送消息的错误状态。
- `cat-template.json.roleTemplates` 是新增猫猫 cloneable 模板的主事实源；legacy disconnected candidates 只作为兼容补充。
- Codex 模型列表可以先由模板/前端 metadata 提供保守默认值，后续再接入账号级可用性接口。
