# [ISSUE-15] 群聊会话排序、群设置展示与消息标记体验回归

**状态**：Resolved
**创建时间**：2026-05-23
**标签**：bug / group-chat / ux / regression

---

## 问题描述

群聊基础能力补齐后，当前在会话列表、群设置、群管理入口、@ 提醒和系统消息展示上仍存在多处体验回归。核心问题是群聊会话的最后消息时间与排序不稳定，且群设置面板中的成员展示、资料编辑、邀请弹窗和状态图标还不符合预期。

当前需要跟踪以下问题：

1. 每次刷新后，群聊会话显示时间都会变成最新的本地时间，而不是最后一条历史消息的时间；会话排序也没有按历史会话最后一条消息时间排序。
2. 点击某个会话后，该会话会从列表中消失或重新排序；进一步观察后发现，点击会话后才会加载并显示真实最后历史消息时间，随后触发二次排序，导致列表顺序跳变。
3. 如图 `09_1`，打开群聊设置时不会先展示所有群成员，只有点击“查看全部”后才会显示成员。
4. 如图 `09_2`，群主无法更改或编辑群公告和群头像。
5. 如图 `09_3`，邀请用户表单使用了浏览器原生 `alert/prompt` 弹窗，不符合产品体验，必须改为自建弹窗组件。
6. 点击“置顶群聊”和“消息免打扰”后，两者的信息图标或状态图标相同，用户无法区分当前状态含义。
7. 群聊中 @ 用户后，被 @ 用户收到的会话提示不是 `[有人@我]` 这种特殊消息标记。
8. 如所有截图所示，类似“你已加入群聊”这类系统消息前面不应再显示发送者名字，应直接显示系统消息内容。

## 复现步骤

### 问题 1：刷新后群聊会话时间变成本地当前时间

1. 登录一个已加入多个群聊、且群聊存在历史消息的账号。
2. 刷新页面或重新登录。
3. 查看左侧会话列表中群聊会话的时间。
4. 预期：群聊会话时间应显示该会话最后一条历史消息的真实时间，并按该时间排序。
5. 实际：多个群聊时间显示为刷新时的本地当前时间，排序也被刷新时间污染。

### 问题 2：点击会话后列表消失或顺序跳变

1. 刷新页面后停留在会话列表。
2. 点击某个群聊会话。
3. 观察左侧会话列表。
4. 预期：点击会话只切换当前聊天，不应导致该会话消失，也不应引发无意义的排序跳变。
5. 实际：点击后该会话可能从列表消失，或因为真实最后历史消息时间此时才被写入而触发重新排序。

### 问题 3：群设置首次打开未展示成员

1. 进入一个已有成员的群聊。
2. 点击打开群聊设置 / 群聊信息抽屉。
3. 预期：群设置面板应立即展示成员概览，成员数量与成员头像 / 昵称应一致。
4. 实际：首次打开时显示“群成员 (0人)”或不展示成员；点击“查看全部”后才显示真实成员，见 `09_1` 与 `09_2`。

### 问题 4：群主无法编辑群公告和群头像

1. 使用群主账号进入群聊。
2. 打开群聊设置。
3. 尝试修改群公告和群头像。
4. 预期：群主应能看到明确的编辑入口，并能保存群公告或上传 / 更换群头像。
5. 实际：群公告和群头像只展示静态内容，无法编辑或更改。

### 问题 5：邀请成员使用原生弹窗

1. 打开群聊设置。
2. 点击“邀请成员”。
3. 预期：展示项目内统一风格的自建弹窗组件，包含输入、取消、确认、校验和错误提示。
4. 实际：浏览器原生弹窗弹出输入框，见 `09_3`。

### 问题 6：置顶与免打扰状态图标无法区分

1. 在群设置中点击“置顶群聊”。
2. 再点击“消息免打扰”。
3. 观察会话列表或群设置中的状态图标。
4. 预期：置顶和免打扰应使用不同图标或不同状态文案，用户能明确区分。
5. 实际：两者图标相同或提示含义不清，用户无法判断当前状态。

### 问题 7：@ 用户缺少特殊会话标记

1. 用户 A 在群聊中 @ 用户 B 并发送消息。
2. 用户 B 查看会话列表和消息提示。
3. 预期：用户 B 的会话摘要应显示 `[有人@我]` 或同等特殊提醒标记。
4. 实际：会话摘要只显示普通文本，不突出 @ 提醒。

### 问题 8：系统消息不应显示发送者名字

1. 查看“你已加入群聊”等群系统消息。
2. 观察会话摘要和消息流中的展示。
3. 预期：系统消息直接显示消息内容，例如“你已加入群聊 xxx”。
4. 实际：系统消息前面仍拼接了用户名字，例如“用户：你已加入群聊 xxx”，信息噪音过重。

## 根因分析

已确认主要原因如下：

1. 前端补齐群聊会话时使用了 `Date.now()` 或本地当前时间作为 `updated_at / last_msg_at` 兜底，覆盖了历史最后消息时间。
2. 后端 `/v1/group/my` 返回的是群资料时间，不是最后消息时间；前端补齐群会话时不能用本地当前时间冒充历史最后消息时间。真实最后消息时间应来自 `/conversation/sync` 或进入会话后的历史消息同步。
3. 群设置抽屉只在组件 mounted 时加载一次群信息和成员，抽屉重新打开时没有可靠刷新成员概览。
4. 群公告 / 群头像已有后端接口，但 UI 编辑入口不够明确。
5. 邀请成员流程仍使用临时的浏览器原生输入弹窗，没有替换为项目内弹窗组件。
6. 置顶和免打扰状态共用了同一个图标或摘要字段。
7. @ 消息的 mention 元数据没有进入会话摘要 / 未读提醒计算。
8. 系统消息类型没有在摘要和消息流中独立处理，仍复用了普通消息的“发送者：内容”格式。

## 问题列表（Q&A 迭代）

### Q1: 群聊会话时间应该以什么字段为准？
**A1**: 应优先使用后端会话同步返回的最后消息时间；若前端需要补齐群会话，也必须基于历史最后消息时间或后端群最近活跃时间，不能使用刷新时的本地当前时间污染排序。

### Q2: 点击会话后为什么会触发排序跳变？
**A2**: 需要确认是否在点击会话并加载历史消息后才更新 `last_msg` 或 `updated_at`。如果是，应把真实最后消息时间提前同步到会话列表，或确保补齐会话时不会先写入错误时间。

### Q3: 群设置首次打开是否应展示全部成员？
**A3**: 至少应展示成员概览，并保证成员数量、角色统计和头像列表与真实数据一致；“查看全部”应进入完整成员管理列表，而不是首次触发真实成员加载的唯一入口。

### Q4: 群主能编辑哪些群资料？
**A4**: 群主至少应能编辑群头像、群名和群公告。管理员权限范围可后续确认，但 UI 与后端都必须按角色做一致校验。

### Q5: 邀请成员弹窗应该怎么做？
**A5**: 应使用项目内统一的 Modal / Dialog 组件，提供 UID 输入、多个 UID 分隔、校验提示、提交状态、取消和确认按钮，不能再使用浏览器原生弹窗。

### Q6: @ 提醒应该在哪里体现？
**A6**: 被 @ 用户至少应在会话列表摘要中看到 `[有人@我]`，并可配合未读数或高亮样式提示；消息流内也应保留 @ 高亮。

## 反馈记录

### 2026-05-23 二次反馈

此前首轮修复后仍存在以下问题，当时需要继续处理，因此本 issue 曾重新打开：

1. **群聊会话时间展示不完整且不符合中文用户习惯**
   - 现象：现在群聊会话统一不显示时间，只有点击进入会话后才会显示时间。
   - 现象：如果最后消息在另一天，例如 2026-05-22，只显示 `May 22`，不显示“昨天”，也不显示具体时分，对中文用户不友好。
   - 预期：会话列表时间应按中文场景格式化：
     - 今天：显示 `HH:mm`。
     - 两天内：显示 `昨天 HH:mm`。
     - 一周内：显示 `星期几 HH:mm`。
     - 超过一周且不超过一年：显示 `MM/DD`，例如 `05/22`。
     - 超过一年：显示 `YYYY/MM/DD`，例如 `2025/03/24`。
   - 注意：一周内的会话必须显示具体时和分。

2. **@ 提醒位置和红点语义不正确**
   - 现象：当前 `[有人@我]` 显示在会话右侧，容易和未读红点混淆。
   - 预期：@ 消息摘要应按顺序显示：左侧先显示红色 `[有人@我]`，然后是用户名，最后是消息内容。
   - 预期：`[有人@我]` 只是特殊摘要标记，不应作为未读红点；红点仍只表示未读数。

3. **只有系统消息的群聊也必须显示系统消息时间**
   - 现象：只有系统消息的群聊可能不显示会话时间。
   - 预期：系统消息也有发出时间；如果会话最后一条是系统消息，仍必须展示该系统消息时间，并参与会话排序。

4. **邀请成员弹窗不可正常输入且一次只能处理一个用户**
   - 现象：邀请成员弹窗点击后直接关闭，无法正常输入。
   - 预期：弹窗应保持可输入状态，支持搜索用户并添加用户。
   - 预期：一次应能搜索并添加多个用户，而不是一次只能搜索 / 添加一个用户。

5. **群主仍然不能设置和编辑群公告、群头像**
   - 现象：群主仍无法实际设置 / 编辑群公告和群头像。
   - 预期：群主应能编辑群公告并保存；应能上传或更换群头像，并看到明确反馈。
   - 需要继续确认：是前端权限判断仍不正确、入口不可达、上传/保存接口失败，还是后端权限校验 / 字段不匹配。

6. **重大问题：有历史发言的群仍显示“你已加入群聊”系统占位**
   - 现象：群里已经有人说过话，但会话列表仍然显示“你已加入群聊 xxx”。
