## 1. 项目背景与目标

### 1.1 背景
随着环境保护意识提升，河流水质监测成为公共管理的重要环节。各级环保部门、水务公司及公众都需要直观、实时地了解河流水质状况，以便及时发现问题、采取措施。

### 1.2 目标
构建一个**移动端优先**的河流水质数据看板，通过可视化方式展示关键水质指标，帮助用户快速掌握河流健康状态。

### 1.3 成功指标
- 页面首屏加载时间 < 3s（3G 网络）
- 移动端适配评分 ≥ 90（Lighthouse）
- 核心水质指标覆盖率 100%（5 项）

## 2. 用户场景

### 2.1 目标用户
| 用户类型 | 使用场景 | 核心需求 |
|---------|---------|---------|
| 环保巡检人员 | 外出巡检时查看站点水质 | 快速定位异常站点、查看实时数据 |
| 水务管理人员 | 办公室/会议中查看整体状况 | 趋势分析、报表概览 |
| 公众/媒体 | 了解周边河流水质 | 直观易懂、状态一目了然 |

### 2.2 用户旅程
```
打开看板 → 查看总览（所有站点状态） → 点击站点查看详情 → 查看历史趋势 → 分享/导出
```

## 3. 功能列表

### 3.1 核心功能

#### F1: 站点总览看板
- **描述**: 以卡片/列表形式展示所有监测站点
- **包含信息**: 站点名称、位置、当前状态（正常/警告/危险）、最后更新时间
- **交互**: 点击卡片进入详情页
- **优先级**: P0

#### F2: 水质指标详情
- **描述**: 展示单个站点的 5 项核心指标
- **指标列表**:
  | 指标 | 单位 | 正常范围 | 警告范围 | 危险范围 |
  |------|------|---------|---------|---------|
  | pH 值 | - | 6.5 - 8.5 | 6.0-6.5 或 8.5-9.0 | < 6.0 或 > 9.0 |
  | 溶解氧 | mg/L | ≥ 5.0 | 3.0 - 5.0 | < 3.0 |
  | 浊度 | NTU | ≤ 10 | 10 - 50 | > 50 |
  | 氨氮 | mg/L | ≤ 1.0 | 1.0 - 2.0 | > 2.0 |
  | 站点状态 | 枚举 | 正常 | 警告 | 危险 |

- **展示方式**: 仪表盘/进度条 + 数值 + 状态标签
- **优先级**: P0

#### F3: 历史趋势图表
- **描述**: 展示近 7 天 / 30 天的指标变化趋势
- **图表类型**: 折线图（支持多指标对比）
- **交互**: 时间范围切换、指标筛选
- **优先级**: P1

#### F4: 数据刷新
- **描述**: 手动刷新 + 自动刷新（每 5 分钟）
- **优先级**: P1

### 3.2 辅助功能

#### F5: 站点搜索/筛选
- 按名称搜索、按状态筛选
- 优先级: P1

#### F6: 分享功能
- 生成当前视图截图/链接
- 优先级: P2

## 4. 数据模型

### 4.1 站点数据 (Station)
```typescript
interface Station {
  id: string;           // 站点唯一标识
  name: string;         // 站点名称（如："黄浦江-外滩段"）
  location: string;     // 地理位置描述
  latitude: number;     // 纬度
  longitude: number;    // 经度
  status: 'normal' | 'warning' | 'danger';  // 综合状态
  lastUpdated: string;  // ISO 8601 时间戳
  metrics: Metrics;     // 水质指标
}
```

### 4.2 水质指标 (Metrics)
```typescript
interface Metrics {
  ph: number;           // pH 值，范围 0-14
  dissolvedOxygen: number;  // 溶解氧，mg/L
  turbidity: number;    // 浊度，NTU
  ammoniaNitrogen: number;  // 氨氮，mg/L
}
```

### 4.3 历史数据点 (HistoryPoint)
```typescript
interface HistoryPoint {
  timestamp: string;    // ISO 8601
  stationId: string;
  metrics: Metrics;
}
```

### 4.4 模拟数据说明
- 使用静态 JSON 数据模拟 5-8 个监测站点
- 每个站点包含当前数据和近 30 天历史数据
- 数据需覆盖正常/警告/危险三种状态，以展示完整 UI 状态

## 5. 界面设计原则

### 5.1 移动端优先
- 设计基准: iPhone SE (375×667) 到 iPhone 14 Pro Max (430×932)
- 触摸目标最小 44×44pt
- 字体最小 14px，关键数据 24px+
- 单手可操作区域优先放置高频操作

### 5.2 视觉层次
- 危险状态: 红色系 (#EF4444)
- 警告状态: 橙/黄色系 (#F59E0B)
- 正常状态: 绿色系 (#10B981)
- 背景: 浅灰/白色系，确保数据突出

### 5.3 信息架构
```
首页（站点总览）
├── 顶部：标题 + 刷新按钮 + 最后更新时间
├── 统计摘要：正常/警告/危险站点数
├── 站点列表（卡片式）
│   └── 点击 → 详情页
│       ├── 站点基本信息
│       ├── 指标仪表盘（5 项）
│       ├── 历史趋势图
│       └── 返回按钮
└── 底部：版权/说明
```

## 6. 技术约束

### 6.1 前端技术栈
- Vue 3 (Composition API)
- 通过 CDN 引入（无构建步骤）
- 图表库: Chart.js 或 ECharts（CDN 版）
- CSS: 原生 CSS + 自定义属性（变量）

### 6.2 性能要求
- 单 HTML 文件，所有资源 CDN 引入
- 首屏渲染 < 3s
- 支持离线缓存（Service Worker 可选）

### 6.3 浏览器兼容
- Chrome 90+
- Safari 14+
- Firefox 88+
- Edge 90+

## 9. 风险与假设

### 9.1 风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| CDN 资源加载失败 | 高 | 使用多个 CDN 源，添加本地 fallback |
| 低端机性能不足 | 中 | 简化动画，减少重绘 |
| 数据模拟不够真实 | 低 | 与领域专家确认数据范围 |

### 9.2 假设
- 用户主要通过移动设备访问
- 数据更新频率要求不高（5 分钟级）
- 无需用户登录/权限控制
