## 问题描述

执行 `sections/agenthub_ui/.ai/plan/V2-test-plan.md` 的 V2-02 注册簇时，注册页未提供“确认密码”字段，密码提示与校验为“不少于6位”，低于计划要求的 `<8 位应拦截`。在 V2-02-02 字段校验中，7 位密码没有被前端拦截，并且实际调用后端完成注册，导致账号 `13800000001` 被提前创建；随后 V2-02-04 使用计划密码 `Test1234!` 注册同一账号时，后端返回 HTTP 400 duplicate。

## 复现步骤

1. 打开 `http://172.18.58.156:5173/#/pages/login/register`。
2. 观察注册表单字段：只有手机号、验证码、昵称、密码，没有确认密码。
3. 填写手机号 `13800000001`、验证码、昵称 `测试员B`、7 位密码，点击“注册账号”。
4. 页面进入聊天页并写入登录态，说明 7 位密码未按 V2 计划被拦截。
5. 再用计划密码 `Test1234!` 注册 `13800000001`。
6. 后端返回 HTTP 400，账号已被步骤 3 提前创建。

## 根因分析

V2 测试计划要求注册链路包含“密码 / 确认密码”，并要求密码 `<8` 位时客户端先于网络请求拦截。当前注册页的 UI 契约仍是“密码不少于6位”，且没有确认密码字段；后端也接受了 7 位密码，说明服务端策略与 V2 计划同样未对齐，导致弱密码注册真实落库。

另有环境追踪风险：5173 运行态登录页已使用 `useAuthStore` 和真实 `/v1/user/*` 接口，但当前 workspace 的 `pages/login/index.vue` 仍含 `mock_token_abc123`。本 issue 的注册页缺陷在运行态与当前 workspace 中一致，但修复前需要先确认当前 dev server 对应的真实源码位置。

## 问题列表（Q&A 迭代）

### Q1: 是不是没有调用后端，所以才注册异常？
**A1**: 不是。`requests-sample.json` 记录到了 `POST http://172.18.58.156:3000/v1/user/register`；`diagnostics.log` 也记录了后续 duplicate 的 HTTP 400。

### Q2: V2-02-03 验证码是否也失败？
**A2**: 校正后判定为通过。真实请求为 `POST /v1/user/sms/registercode`，页面出现倒计时。原始 report 中的 `API 调用数=0` 是 runner 路径匹配漏掉 `/v1/user/*`。

### Q3: 为什么 V2-02-04 被标记为 Blocked / Fail？
**A3**: 因为 V2-02-02 已把计划账号 B 提前注册，V2-02-04 无法再按原计划创建 `13800000001 / Test1234! / 测试员B` 的干净账号。
